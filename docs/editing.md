# Editing the book's text

You read the book in your browser and fix sentences in place. Nothing about the site changes, and the tooling never ships: `tools/` isn't copied into the published site.

## One-time setup

1. Start the local server from the project folder:

   ```bash
   python3 tools/serve.py
   ```

   The book is at http://localhost:8765.

2. Make a bookmark in your browser (any name, "Edit book" works) and paste this as its **URL**:

   ```
   javascript:(function(){var s=document.createElement('script');s.src='/tools/edit-mode.js';document.body.appendChild(s);})()
   ```

   In Safari you may need to enable Develop → "Allow JavaScript from Smart Search Field"; in Chrome it works as is. If your browser refuses bookmarklets, open the page, press ⌥⌘J for the console, and paste the same code without the leading `javascript:`.

## Editing

1. Open a chapter and click the bookmark. Paragraphs get a dashed outline.
2. Click into any paragraph, heading, caption, quiz question or list item and type. It's a normal text field. Enter finishes the edit; shift+Enter makes a line break inside the paragraph.
3. Edited paragraphs get an orange bar so you can see what you changed.
4. Your `ANURAG:` story prompts appear inline as yellow notes, so you can answer them where they belong.
5. Keep reading. Edits are remembered across chapters and survive a reload, so you can do a whole session in one go.
6. When you're done, click **Copy edits** in the bar at the bottom right and paste it into chat, or **Download** to get an `edits.json` file.

The **Discard** button throws away every stored edit, including ones from other chapters. It asks first.

## Applying them

Either hand me the JSON and I'll apply it, or do it yourself:

```bash
python3 tools/apply-edits.py ~/Downloads/edits.json
```

That's a dry run: it prints each change with the surrounding words, marking the changed part in brackets. To write the changes:

```bash
python3 tools/apply-edits.py ~/Downloads/edits.json --write
```

Each edit carries the exact text it replaces. If a paragraph changed after you edited it (say, I rewrote it in the meantime), that edit is reported as stuck and **nothing is written** until it's resolved. `--force` applies the ones that did match and skips the rest.

After applying, check the result:

```bash
node tests/run-tests.js --quick
```

Then commit and push as usual.

## What you can't edit this way

- **Widget output** (tables, charts, numbers computed from your stack). Those are generated by code; tell me and I'll change the code.
- **Math** rendered by KaTeX, and anything inside a code exercise.
- **Structure**: adding or removing whole paragraphs, sections or callouts. Edit mode changes text inside existing blocks. For structural changes, just tell me what you want.
